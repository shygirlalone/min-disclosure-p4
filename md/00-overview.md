# 加密传输最小披露 — 课题总览

## 研究动机

QUIC 隐藏了 deadline、剩余数据量和服务类型。网络难以在不获得这些信息的前提下实施精确调度、诊断和路径优化。现有解决路径存在两种极端：

1. **直接暴露优先级、deadline 或测量字段** —— 网络能正确决策，但会持续泄露应用行为和传输状态。
2. **根据包长、间隔、方向等外部特征推断** —— 不泄露字段，但准确性和鲁棒性不足，无法作为可靠控制依据。

实际上，交换机通常不需要知道"该流的 deadline 是 7.3 ms"或"还剩 42 KB"；它只需要知道当前应执行什么动作。

## 核心 insight

> 将传统的"暴露状态字段"改为"暴露受约束的动作标签"。

- 传统：`Server private state → deadline / size / loss fields → switch decides action`
- 本文：`Server private state + switch context → action label → switch executes action`

对于特定的网络功能，网络本身不需要端点状态；它只需要足以在当前网络上下文下执行该功能的最小决策输出。**可观测性应该由可执行的决策来定义，而不是可重用的状态字段。**

## 三个贡献

| 贡献 | 内容 |
|---|---|
| **1. 决策级最小披露模型与理论保证** | 提出 action-level observability；形式化证明只返回动作是完成指定精确决策所需的最小语义披露。含决策充分性 `G(L(x,z),z)=F(x,z)`、精确泄露恒等式 `I(X;L\|Z)=H(A\|Z)+I(X;η\|A,Z) ≥ H(A\|Z)`（动作标签取等）、私有状态不可区分性、跨时间组合泄露 `Λ_T=H(A_{1:T}\|Z_{1:T})` 与 Pareto frontier |
| **2. 上下文绑定的动作标签生成与更新协议** | ★ **Week1 交付这个**。静态优先级提示 → 由实时网络上下文触发、有限状态范围内缓存复用、状态变化后自动失效的短期动作协议 |
| **3. 服务器—交换机协同执行框架** | 控制面 contract `C=⟨subject, flow scope, function, contexts, allowed actions, quota, update rate, validity⟩`，防止服务器无限制地把所有流标记为 HighPriority |

## Week1 范围（本工作区）

贡献 2 的 (1)(2) 两部分：

**(1) 交换机侧状态获取 + 判断**
- 读取三个指标（队列拥塞等级、端口负载、路径可用性），存入寄存器
- 设计交换机→服务器的**上报协议**：某指标越过手设阈值时，把协议挂到数据包上发给服务器
- 上报后清空寄存器，直到收到服务器新标签为止，这段时间**只做正常转发**，不执行任何已定义功能

**(2) 服务器→交换机的动作标签协议**
- 字段长度自定义
- 覆盖 `<flow_id, function_id, context_id, action_id, epoch, expiry, sequence>`

**不在 Week1 范围**：contract 管理（贡献 3）、需要 ingress 的动作（切路径）、真实加密（Week1 用 CRC16 占位）。

## 对比方案

| 方案 | 出处 | 差异 |
|---|---|---|
| **PLUS** | 2017 CNSM | 端点向路径设备显式发送可测量、可扩展的信号。一旦暴露，沿路设备可反复观察复用；不回答"完成某个动作最少要暴露什么"，也不把信号绑定到具体功能、当前上下文和短期有效期 |
| **Sidekick** | 2024 NSDI | 信息方向是"网络观察流量状态，再反馈给端点"，网络节点对 opaque packets 形成紧凑选择性确认反馈给发送端，最终由端点改变行为；不支持交换机根据端点私有状态直接执行动作。本文解决**反向问题** |
| **Mazu** | 2025 SIGCOMM | 不依赖端点合作，靠包长/方向/时序被动推断。推断结果无法可靠恢复 deadline、remaining size 或真实重传状态，也不具备用途授权和最小披露保证 |
