# 07 — 服务器规则模型与最小披露（简化版）

> 这是一份**独立、简化**的版本，用于讲解与答辩；完整推导见 `md/06`。
> 两个问题：（1）服务器怎么决定「做什么」？（2）为什么只说「做什么」就够了？

---

## 1. 模型

### 1.1 输入：私有 4 个 + 网络 3 个

| 输入 | 含义 | 来源 | 范围 |
|---|---|---|---|
| `r` | 剩余字节数 | 应用层 | > 0 |
| `rho` | 重传比例 | 传输层统计 | [0, 1) |
| `D` | 希望多久内送完（有 deadline 用 deadline，没有用业务期望时延） | 应用层 / 业务配置 | > 0 |
| `w` | 业务权重 | 业务配置 | [0, 1] |
| `q` | 队列等级 | 交换机上报 | 0..15 |
| `load` | 端口负载等级 | 交换机上报 | 0..15 |
| `avail` | 路径可用 | 交换机上报 | 0 / 1 |

`C` 是**链路能力**：标称容量，或长期基线速率（如 100 Mbps）。它只是一把尺子，不是判决阈值；
不要用瞬时速率——当前拥堵已由 `c` 表达，两边都算就重复了。

`deadline` 与 `latency sensitivity` 合并为一个 `D`：有硬期限用期限，没有用业务能接受的时延，不写分支。

### 1.2 三个公式

```text
r_eff = r / (1 - rho)                  # 重传会放大实际要发的量
u     = w * (r_eff / D) / C            # 急迫度：占链路能力 C 的几成（可 > 1）
c     = ( q/15 + load/15 + (1 - avail) ) / 3   # 拥堵度：三信号平均
level = round( 7 * min(1, u * c) )     # 0..7 档
```

- `u` **先不截断**：需要 3 倍链路能力的流，`u = 3`，比 `u = 1` 更该加急。
- 截断只发生在最后一档（总共 8 档），是动作空间的大小，不是归一化造成的。

### 1.3 决策

```text
level == 0  ->  不发标签（纯转发，NOOP）
level >= 1  ->  买优先级，档位 = level
avail == 0 且存在备用端口  ->  直接切路（PORT_REDIRECT），不参与买带宽
```

**为什么是乘**：加急要两个条件同时成立——网络不堵（`c=0`）时加急没好处，流不急（`u=0`）时花钱不值，
两种都让 `level=0`。

**为什么没有阈值**：升几档是 `round(7·u·c)` 连续算出来的；「不发」只是四舍五入落到 0，
不是「队列超过 8 就升级」。

### 1.4 伪代码

```text
# 每收到一份上报 z，对每条流调用一次
decide(x, z):
    # 1) 私有侧：有多急
    r_eff = r / (1 - rho)
    need  = r_eff / max(D, 1ms)
    u     = w * need / C                 # 可 > 1，先不截

    # 2) 网络侧：有多堵（三信号平均）
    c = (q/15 + load/15 + (1 - avail)) / 3

    # 3) 路坏了先切路
    if avail == 0 and has_backup():
        return REDIRECT(backup_port())

    # 4) 急 × 堵 → 档位
    level = round(7 * min(1, u * c))     # 只在这里截
    if level == 0: return NOOP           # 不发标签
    return PRIORITY(level)
```

### 1.5 一个例子

`q = 9`、`load = 9`、`avail = 1` → `c = 0.4`；`C = 100 Mbps`。

| 流 | 私有情况 | `u` | `u×c` | 结果 |
|---|---|---|---|---|
| A 视频会议 | 120 KB，15 ms 到期，`w=0.9` | 0.60 | 0.24 | `level=2`，买 |
| B 批量备份 | 很大，但没期限 | 0.00 | 0 | 不发 |
| C 同 A，网络空闲 | 同 A，但 `q=load=0` | 0.60 | 0 | 不发 |

B 和 C 是一对反例：**只看网络会误判 B，只看私有状态会误判 C**。

## 2. 理论分析

### 2.1 记号

- `X`：私有状态（`r`、`D`、`w`、`rho` 打包）
- `Z`：网络上下文（`q`、`load`、`avail`，公开）
- `A = F(X,Z)`：动作（`PRIORITY_SET` / `PORT_REDIRECT` / `ECN_MARK` / `NOOP`）
- `L = (A, M)`：线上标签，`M` 为元数据（`context_id`、有效期等）
- `G`：执行器，只校验、不重算

### 2.2 决策充分性

**定义**：若对任意 `(x,z)` 有 `G(L(x,z), z) = F(x,z)`，称接口是**充分**的。

- **构造**：`L = (F(x,z), η(z))`，`G` 在「未过期 + 版本匹配 + 白名单」下直接输出 `A`。
- **必要性**：若两个私有状态产生不同动作却共享同一标签，任何执行器都只能返回其中一个，
  必然对另一个出错。所以**动作身份不能合并**。

### 2.3 最小披露

用条件互信息度量泄露：`leak = I(X; L | Z)`。

**定理（精确分解）**：设 `A = F(X,Z)` 确定，则

```text
I(X; L | Z) = H(A | Z) + I(X; M | A, Z)
```

*证明*：链式法则 `I(X;A,M|Z) = I(X;A|Z) + I(X;M|A,Z)`；又 `A` 是 `(X,Z)` 的确定函数，
`H(A|X,Z)=0`，故 `I(X;A|Z) = H(A|Z)`。代回即得。∎

**推论**：

- 下界 `I(X;L|Z) ≥ H(A|Z)`；等号当且仅当 `I(X;M|A,Z) = 0`，即 `X ⊥ M | (A,Z)`。
- 取 `M` 只依赖 `(A,Z)`（`context_id` 原样回填、有效期由上报间隔统计决定），即可达下界。
- 因此：对确定性规则，`H(A|Z)` 是完成一次精确决策的**最小**语义披露，动作标签恰好达到它。

### 2.4 不可区分性

若 `F(x₁,z) = F(x₂,z) = a`，则任何只由动作派生的标签都有 `L(x₁,z) = L(x₂,z)`；
若 `M` 只依赖 `(A,Z)`，还有 `P(x | L, z) = P(x | A, z)`——同一动作类内，后验不再变化。

例：三个 deadline（15 / 25 / 40 ms）都被判为 `PRIORITY_SET(4)`，交换机只知道「进 4 档」，
不知道是哪一个。**类内信息没有被披露。**

### 2.5 动作粒度是隐私旋钮

动作档位越多，私有状态被切得越细，单次可区分的信息越多；档位越少，不可区分类越大，泄露越少，
但控制也越粗。

```text
{x₁,x₂,x₃} -> PRIORITY(4)     # 想区分 15ms 与 25ms，就得多一档
{x₄,x₅}    -> ECN
{x₆}       -> NOOP
```

**没有免费的分辨率**：控制精度与披露量同向增长。

### 2.6 多轮与加密

```text
I(X; L₁..L_t | Z₁..Z_t) ≤ Σ H(Aᵢ | Zᵢ)
```

每个新网络状态最多贡献一次「这一轮动作是什么」，同状态重复发标签不增加信息。
量化桶做粗，既减少状态数，也减少累计泄露。

加密（AEAD / 带密钥码本）只把密钥发给**需要执行动作的交换机**（通常是边缘/入口那台）：
链路旁观者看不到，中间交换机不解密，持钥者仍只拿到 `H(A|Z)`。不保护时序、包数、包长等侧信道。

### 2.7 与 `md/06` 的对应

| 本文 | md/06 | 说明 |
|---|---|---|
| `u`（急迫度） | `v`（支付意愿） | 一阶简化：把「吞吐价值 + 时效价值」压成「需要的速率占比」 |
| `c`（拥堵度） | `μ`（影子价格） | 一阶简化：指数价格线性化成三信号平均 |
| `level = round(7·min(1,u·c))` | `h* = round(H_max·clip((v−μ)πc/β,0,1))` | 同一形状：私有侧 × 网络侧；去掉 `β`、`clip` |
| 动作：PRIORITY / REDIRECT / NOOP | 含 ECN / DROP | 简化版省略 ECN |

模型怎么简化，只影响 `H(A|Z)` 的大小，不影响「只发动作即最小」这个结论——
因为定理只要求 `F` 是确定函数。

## 3. FAQ

**Q1：`C` 为什么是链路能力，而不是固定常数？**
固定常数换条链路就失效；用标称容量或长期基线，`u` 才能解释成「我需要的能力占正常能力的几成」。

**Q2：为什么 `u` 不早截断？**
截到 1 会丢掉「超额多少」的区别（`u=2` 与 `u=100` 一样）。保留原值、只在最后档位处截，
网络不太堵（`c` 小）时，超额多的流仍能拿到更高档位。

**Q3：「不发标签」算不算披露？**
算。没收到标签本身是可观测事件，等于告诉对方「这一轮是 NOOP」，已计入 `H(A|Z)`。
真正的零披露是：该网络状态下动作与私有状态无关（`H(A|Z)=0`），此时规则应固化在交换机里。
