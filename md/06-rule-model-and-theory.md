# Part A — 服务器规则生成模型

## A.1 一句话

**交换机上报的 context 是价格，服务器的私有状态是支付意愿，动作标签是两者在边际上成交的结果。**

```
        服务器私有状态 x                          交换机上报 z
 ┌──────────────────────────┐          ┌───────────────────────────┐
 │ r   剩余字节              │          │ q̃  队列等级 (0..15)/15     │
 │ D   剩余 deadline         │          │ l̃  负载等级 (0..15)/15     │
 │ w   业务权重              │          │ ã  路径可用 (0..15)/15     │
 │ ρ   重传比例  σ  RTT 膨胀 │          │ ctx_id、timestamp          │
 └────────────┬─────────────┘          └─────────────┬─────────────┘
              │ 支付意愿 v                            │ 影子价格 μ
              └───────────────┬───────────────────────┘
                              ▼
                   ┌────────────────────────┐
                   │   v > μ  → 买优先级     │
                   │   v < μ  → 让出带宽     │
                   │   都不成立 → 不发标签   │
                   └───────────┬────────────┘
                               ▼
                      action_label_t (24 B)
```

所有决策都归到同一个比较 `v > μ`。**没有"队列超过 X 就升优先级"这类判决阈值**：
`μ` 由上报的 context 连续决定，`v` 由私有状态连续决定，动作档位是两者之差的量化结果。

### A.1.1 理论基础：对偶分解

把网络看成受容量约束的社会福利问题：

```text
    max  Σ_f U_f(R_f)          s.t.  Σ_f R_f ≤ C
```

拉格朗日乘子 `μ` 是带宽的**影子价格**。对偶分解后：

```text
    网络侧：只需要广播 μ
    端点侧：本地求解  max_R  U_f(R) − μ·R
```

本文的协议正是这个分解的一个实现：

| 对偶分解里的量 | 协议里的对应物 |
|---|---|
| `U_f` | 服务器私有状态 `x` 定义的用户效用 |
| `μ` | 交换机上报的 context `z` 经标定得到的代理价格 |
| 本地最优动作 | 动作标签 `L` |

所以"减少阈值"不是风格问题，而是**结构问题**：价格随网络状态连续移动，判决边界
自然随 context 移动，不需要一组手调常数去近似它。

> 严格性说明：deadline 惩罚项使 `U_f` 不一定凹，本文**不声称全局最优或强对偶成立**。
> 对偶分解只作为"用统一价格协调独立决策"的结构性依据；`μ` 是 context 的**代理价格**，
> 由标定得到，不是网络真实的对偶变量。

## A.2 输入

### A.2.1 私有状态 `x`（服务器本地，永不出域）

| 符号 | 含义 | 量纲 / 范围 | 服务器从哪来 |
|---|---|---|---|
| `r` | 流剩余字节数 | byte，`>0` | 应用层（Content-Length − 已确认字节） |
| `D_rem` | 距 deadline 的剩余时间；无硬 deadline 时取 `∞` | s，`>0` 或 `∞` | 应用层 |
| `w` | 业务优先级权重（连续） | `[0, 1]` | 业务配置：按服务等级初始化，再连续微调（**不是等级阈值**） |
| `λ` | baseline latency sensitivity | `[0, 0.9]` | 业务配置：无 deadline 也讨厌排队/抖动的程度（见 A.2.4） |
| `ρ` | 重传比例 | `[0, 1)` | 传输层统计（重传字节 / 总发送字节） |
| `R̂` | 当前发送速率 | Mbps | ACK 时钟估计 |
| `σ` | RTT 膨胀比（发送端观测的排队代理） | `≥1` | `RTT_smooth / RTT_min`（**估计量**，见 A.2.4） |

> **业务优先级 → `w`；deadline 或 latency sensitivity → `D_rem` / `λ`；
> 发送端拥塞与重传 → `R̂` / `ρ` / `σ`。** 这四项覆盖用户列出的私有状态，
> 且全部是连续量；服务等级只影响 `w`、`λ` 的**初值**，不参与判决。
>
> `w = 0` 是合法状态（纯让路流）：它不影响其他流的判决，只让本流的吞吐价值为 0。

### A.2.2 网络上下文 `z`（交换机上报，14 B）

| 符号 | 来源字段 | 归一化 |
|---|---|---|
| `q̃` | `queue_level`（0..15） | `q̃ = queue_level / 15` |
| `l̃` | `load_level`（0..15） | `l̃ = load_level / 15` |
| `ã` | `path_level`（0..15） | `ã = path_level / 15` |
| `ctx_id` | `context_id`（32 bit） | 直接使用 |
| `t_s` | `timestamp`（16 bit tick） | 用于算上下文年龄 |

`l̃` 的语义是**端口包速率 / 端口容量**（单位时间包数），交换机 4 bit 量化后
上报为 `load_level`。当前实现用 `deq_timedelta`（排队时延）代理，方向是反的
（D30）；**D30 修好之前，模型只用 `q̃` 与 `ã`，把 `l̃` 置 0**。模型本身不依赖
具体量化桶，只要求"等级越大 = 该指标越紧张"。`Δq̃⁺` 与 `age` 都是上报序列的
零成本派生量，不增加任何线格式字段。

### A.2.3 派生量（全部在服务器侧算，不增加任何线格式字段）

```text
r_eff  = r / (1 - ρ)                              # 重传折算后的有效剩余量
slack  = D_rem - r_eff / R̂                        # 按当前速率还需多久 vs 还剩多久
u      = 1 - (1 - exp(-max(0, slack) / T_v))·(1 - λ)
                                                  # 时效紧迫度 ∈ [λ, 1]
Δq̃     = q̃_now - q̃_prev                          # 两次上报之间的等级变化
Δq̃⁺    = max(0, Δq̃)                              # 只关心"变差"的方向
age    = now - t_s                                # 上下文年龄
c      = exp(-age / T_age)                        # 新鲜度折扣 ∈ (0,1]，无硬下限
```

| 派生量 | 作用 | 没有它会怎样 |
|---|---|---|
| `slack` | 把 deadline 与剩余量合成"还剩多少余量" | 只看 deadline 会误判大流/小流；大流即使 deadline 很远也可能已经很紧 |
| `u` | deadline 越近越紧迫；无 deadline 的流也有 `λ` 的基线紧迫度 | 只看 `D_rem` 会漏掉 latency-sensitive 弹性流；用 `D < X` 判紧迫就是硬阈值 |
| `Δq̃⁺` | 区分"拥塞在恶化"与"正在恢复" | 单次等级看不出方向 |
| `c` | 旧 context 连续降低动作幅度；旧到一定程度自然不发标签 | 用陈旧上下文做激进动作；加硬下限反而让很旧的 context 仍有 20% 动作幅度，不够 fail-safe |

### A.2.4 新增的可行参数（都不改线格式）

0. **`λ` baseline latency sensitivity（服务器侧，业务配置）**
   取值 `[0, 0.9]`，表示"没有硬 deadline，也愿意为避免排队/抖动付多少"。
   它把用户需求里的 **deadline 或 latency sensitivity** 两种情况统一进 `u`：
   `D_rem = ∞` 的弹性流得到 `u = λ`，而不是 0。
   `λ` 必须小于 1：`λ = 1` 会让 `u ≡ 1`，弹性流的 ECN 分支永远不可达，
   模型退化成"总是买"。典型值：交互式 `0.2–0.4`，批量 `0`，直播 `0.5–0.7`。

1. **`σ` RTT 膨胀比（服务器侧，传输层已有）**
   `RTT_min` 近似无排队基线，`RTT_smooth / RTT_min` 是发送端**自己看到**的排队程度。
   用途：当 `q̃` 很低而 `σ` 很高时，说明排队发生在本交换机下游，本交换机不该
   过度反应。它是**估计量**，受 ACK 压缩、采样噪声与路径变化影响；它属于
   X 侧却修正 Z 侧的价格，这是有意的跨侧耦合，不应被误读为"价格完全由网络决定"。
   可选修正：

   ```text
   q_eff = max(q̃, clamp((σ - 1) / κ_σ, 0, 1))
   ```

   把 `q_eff` 代入 A.3 的 `π`。不启用时 `q_eff = q̃`，模型不变。

2. **队列趋势 `Δq̃⁺`**：两次报告的等级差。协议已经是"变化才上报"，服务器天然
   会看到等级序列，趋势是**零成本**派生量。

3. **上下文新鲜度 `c`**：报告自带 `timestamp`，年龄可算。用途不是判"过期/不过期"
   （那是 expiry 的事），而是**连续降权**：`c = exp(-age/T_age)`，不设硬下限。
   上下文旧到 `c→0` 时动作幅度归零，等价于不发标签；这比"旧 context 仍保留
   20% 动作"更 fail-safe。

4. （可选）**自身份额 `R̂ / C_link`**：数据中心内链路速率已知，服务器可算自己
   占了多少。用于在价格之外识别"我自己就是拥塞源"，避免自己给自己加价。

5. （可选，**不进核心公式**）**发送窗口利用率**：
   `g = clip(RTT·R̂ / (cwnd·MSS·8), 0, 1)`，即 in-flight 字节 / BDP。
   `g≈1` 表示发送端受窗口限制（网络瓶颈，加优先级有用）；`g≪1` 表示应用受限
   （加优先级买不到多少速率）。若启用，应把它作为 `v` 的乘性门控或对 `R̂` 的
   置信修正，而不是直接塞进 `μ`。本版不启用，避免把"发送端状态"与"网络价格"
   混为一谈；它的作用是提醒：`R̂→0` 时 `r_eff/(T_v·R̂²)` 会爆炸，必须有 `R_MIN` 守卫。

## A.3 决策过程

### A.3.1 第一步：私有侧 → 边际价值 `v`

流的效用取"对数吞吐 + 时效惩罚"：

```text
U(R) = w · log(1 + R/R0) − exp(−max(0, slack(R))/T_v),
slack(R) = D_rem − r_eff/R
```

在当前速率 `R̂` 处的边际价值：

```text
v = w / (R0 + R̂)  +  u · r_eff / (T_v · R̂²)
    └─── 吞吐价值 ───┘  └──── 时效价值 ────┘

u = λ + (1 − λ) · exp(−max(0, slack)/T_v)         ∈ [λ, 1]
```

- **第一项**：再快一点的吞吐收益，随 `R̂` 递减（凹效用）。`w` 是连续的
  业务优先级权重，不是"高/中/低"三档。
- **第二项**：deadline 与延迟敏感共同形成的时效价值。`u` 连续：`slack ≫ 0`
  时趋近 `λ`（只有基线延迟敏感）；`slack ≤ 0` 时饱和到 1。两种写法等价
  （`1 − (1−e)(1−λ) = λ + (1−λ)e`），第二种写法让"凸组合"一目了然。
- **`λ > 0` 时不声称 `v` 是单一 `U` 的导数**：`λ = 0` 时第二项系数恰好等于
  `∂U/∂R`；`λ > 0` 时把基线紧迫度作为常数项并入 `u`，是主动的建模选择
  （让无 deadline 的弹性流也能出价），不对应任何单一效用函数。推导顺序是：
  先对 `λ = 0` 的 `U` 求导，再做凸组合。
- **弹性流**：`D_rem = ∞ → slack = ∞ → u = λ → v = w/(R0+R̂) + λ·r_eff/(T_v·R̂²)`。
  `λ = 0` 退化为纯吞吐价值；`λ > 0` 表达"没有硬 deadline 但讨厌排队"。
  不需要"是否 deadline 敏感"的分支。
- `ρ` 通过 `r_eff` 进入。**注意不要声称 `v` 对 `ρ` 单调**：`ρ↑` 使 `r_eff↑`，
  在 `slack > 0` 时通常抬高 `v`；但一旦到期（`slack ≤ 0`），时效项饱和，
  剩余率变差可能反而降低 `v`。模型只保证 `v` 连续，不保证对每个私有量单调。
- **边界延拓**：严格地说，`λ = 0` 且 `slack > 0` 时 `v` 是 `U` 的导数；
  `slack ≤ 0` 时 `u` 饱和为 1，`v` 取**边界延拓**（继续按最高紧迫度计价），
  以保持连续、避免动作在 deadline 处跳变。若按严格导数，饱和区时效价值为 0，
  判决会在 deadline 处出现台阶。这是有意的建模选择，论文中应写明。
- `v` 与 `μ` 使用同一套**归一化价值/价格单位**；示例常数是无量纲标定值，
  不声称对应真实货币或物理单位。

### A.3.2 第二步：网络侧 → 影子价格 `μ`

```text
π  = clip( (q_eff + l̃ + (1 − ã)) / 3 + κ_t · Δq̃⁺,  0, 1 )
μ  = μ0 · exp(κ_π · π)
```

- `π` 是**稀缺度**：队列 `q_eff`、端口负载 `l̃`（包速率/容量）、路径不可用
  `1−ã` 三路取平均，再叠加恶化趋势。三路等权是可解释的默认；若要强调某一维，
  可换成权重 `α_q+α_l+α_a=1`，但本版不增加这三个标定参数。
- `μ` 是**每单位速率的边际成本**（影子价格的代理）。指数形式让价格在拥塞
  加深时快速上升，且永远为正；`μ0` 与 `v` 同量纲，保证"网络空闲时 μ 很小、
  网络打满时 μ 足够大"。
- `μ0` 是单位标定量；所有决策只依赖 `v` 与 `μ` 的**相对大小**，把 `U` 与
  `μ0` 同时乘一个常数不改变动作。但只缩放 `w`（例如把所有业务权重减半）
  会改变哪些流愿意出价，因此不能说"绝对尺度无关"。
- `κ_π` 是价格的拥塞弹性：越大，拥塞加深时价格上升越快；它决定决策曲线在
  `π` 轴上的陡峭程度，不是判决阈值。
- `κ_t` 让"正在恶化"比"已经恶化但正在恢复"更贵；`Δq̃⁺` 只取变差方向。

### A.3.3 第三步：候选动作的净收益

动作集合按实现状态分两层：

| 动作 | 参数 | 可用性 | 语义 |
|---|---|---|---|
| `NOOP` | — | ✅ | 纯转发；**也可以选择不发标签** |
| `PRIORITY_SET(h)` | `priority = h ∈ 0..7` | 标签可收；egress 空执行 | 买带宽 |
| `ECN_MARK` | — | ✅ egress | 让出带宽（软） |
| `PORT_REDIRECT(p)` | `egress_port = p` | ✅ ingress | 换路径（可行性动作） |
| `DROP` | — | ✅ egress | **不由本模型选择**（见下） |
| `MEASURE` | `action_id` | Week2 | 让网络测这一流 |
| `RATE_LIMIT` | 无参数字段 | ❌ 拒收 | 不用 |

每个动作族按自己的净收益判据比较。**不把"买优先级"和"让带宽"硬塞进同一个
argmax**：前者是连续档位，后者是二元信号加一次操作成本，二者成本结构不同；
分别写出判据比假装存在统一效用更诚实。

**优先级档位**：令 `x = h/H_max ∈ [0,1]`，在给定 context 下解

```text
max_{x∈[0,1]}   (v − μ) · π · c · x  −  (β/2) · x²
```

线性项是"每提高一档优先级带来的净剩余"，二次项是控制/公平成本（凸）。
目标对 `x` 是凹的，一阶条件 `β·x = (v−μ)·π·c` 给出

```text
x* = clip( (v − μ) · π · c / β,  0, 1 )
h* = round( H_max · x* )
```

```text
若 v > μ 且 h* ≥ 1：输出 PRIORITY(h*)
若 v ≤ μ：          J_ECN = (μ − v) · π · c · δ − κ_ecn
                    若 J_ECN > 0：输出 ECN_MARK
否则：              NOOP（不发标签）
```

为什么 `h*` 里同时出现 `(v − μ)` 和 `π`：

- 私有侧越急（`v − μ` 大）→ 档位越高；
- 网络越稀缺（`π` 大）→ 优先级才越有实际效果；`π = 0` 时买优先级没有意义；
- `c` 让陈旧 context 下的动作幅度变小；
- 任一因子为 0 → `h* = 0` → 不发标签。**这就是"同时考虑两部分参数"的直接体现**。

`β` 是档位增益的标定常数：`β` 越小，同样的剩余会买到更高档位；它**不是**
状态判决阈值。`round` 把连续档位映射到动作字母表，`H_max = 7` 是策略选择
（不是字段上限 `PRIORITY_MAX = 0xF`）；`|𝒜|` 因此成为披露旋钮（见 Part B）。

**`PORT_REDIRECT` 是可行性覆盖，不参与价格比较**：

```text
若 ã = 0 且存在可用备用端口 p：直接输出 PORT_REDIRECT(p)
```

`ã = 0` 是"当前路径不可用"的语义（等级 0），不是可调阈值。

**`DROP` 不由服务器选择**：丢包只会触发重传，对流的效用是负的，自利服务器不会选。
它保留给契约违约、标签吊销等**网络侧安全动作**。

**`MEASURE`**：放在 A.3.3 之外的可选层。只有当决策对上下文敏感
（`v` 与 `μ` 接近）且上下文陈旧时，信息价值才为正；Week2 S3 再展开
（`J_MEAS = EVSI − κ_meas`）。

### A.3.4 第四步：有效期

```text
τ = clamp( α · EMA(Δt_report),  τ_min,  τ_max )
expiry_ticks = round( τ / 65.536 µs )
```

**关键设计约束：有效期只能由 context 的观测统计决定，不能由私有状态决定。**
若用 `D_rem` 去算 `τ`，标签就额外泄露了 deadline（见 Part B 的 B.3 备注）。
`α / τ_min / τ_max` 是标定量与安全边界，不是判决阈值。

**因果约束**：第 `t` 轮签发的标签，只能通过 `F(X, Z_t)` 依赖私有状态 `X`；
不能在 `t` 之后用新的私有状态改写已签发的标签。否则标签会携带"签发之后才
知道"的私有信息，Part B 的 `I(X;η|A,Z)=0` 条件不再成立。

### A.3.5 第五步：输出

| 模型输出 | 线字段 | 取值 |
|---|---|---|
| 动作函数 | `function_id` | `NOOP` / `PRIORITY_SET` / `ECN_MARK` / `PORT_REDIRECT` |
| 动作参数 | `priority` / `egress_port` | 按函数；`h` 复用 `priority` 字段 |
| 审计档位 | `action_id` | 可镜像 `h`，或做版本追溯 |
| 上下文绑定 | `context_id` | **原样回填**收到的 `ctx_id` |
| 纪元 | `epoch` | 服务器纪元（策略切换 +1） |
| 有效期 | `expiry` | 相对 tick 偏移 |
| 防重放 | `sequence` | 单调递增 |

**`NOOP` 的输出就是"不发标签"，但"不发"不等于"零披露"**。这是最容易说错的一条：

- 对**该流的数据包**，交换机停在 `REPORTED`，纯转发，行为与部署前逐比特一致；
- 但"没有收到标签"本身是可观测事件，语义是 `A=NOOP`。如果同一 context 下
  有的流拿标签、有的流不拿，"不拿"就泄露了"这条流落在 NOOP 动作类"。
  这部分信息**已经计入 `H(A|Z)`**，不是零披露；
- 真正的零披露条件是：该 context 下动作与私有状态无关，`H(A|Z=z)=0`。
  此时服务器一个字都不该发，规则应下推到交换机的本地策略 `b(z)`
  （前提是交换机可执行 `b(z)`）；否则仍需要一个最小的动作接口；
- 下一轮 `context_id` 变化会让旧标签自然失效，不需要显式吊销。
  只有"同一轮 context 内要中途取消"才用 `LABEL_REVOKE`（`msg_type=2`）。

## A.4 伪代码

```text
# 服务器侧：每收到一份 ctx_report 调用一次
decide(x, z):
    # 0) 同一轮 context 复用缓存：不重复决策，也不重复披露
    if z.ctx_id == cache.ctx_id and now < cache.expiry:
        return cache.label

    # 1) 数值守卫：把病态输入变成安全动作（不是判决阈值）
    if x.rho >= 1 - EPS:                 # 重传比例病态，参数不可信
        return None                      # NOOP：不发标签
    R = max(x.R_hat, R_MIN)              # 防止 R_hat -> 0 时 1/R^2 爆炸
    r_eff = x.r / (1 - x.rho)

    # 2) 私有侧：折算成"每单位速率的支付意愿" v
    slack = x.D_rem - r_eff / R
    u = 1 - (1 - exp(-max(0, slack) / T_V)) * (1 - x.lam)
    v = x.w / (R0 + R) + u * r_eff / (T_V * R * R)

    # 3) 网络侧：折算成"每单位速率的影子价格" mu
    q_eff = max(z.q/15, clamp((x.sigma - 1) / K_SIGMA, 0, 1))   # 可选
    pi = clip((q_eff + z.l/15 + (1 - z.a/15)) / 3 + K_T * z.dq_pos, 0, 1)
    mu = MU0 * exp(K_PI * pi)

    # 4) 可行性覆盖：当前路径不可用
    if z.a == 0 and exists_alternative_port():
        return make_label(REDIRECT(best_port), z)

    # 5) 新鲜度与价格比较
    c = exp(-z.age / T_AGE)              # 无硬下限；过旧自然 -> 0
    if v > mu:
        h = round(H_MAX * clip((v - mu) * pi * c / BETA, 0, 1))
        if h >= 1:
            return make_label(PRIORITY(h), z)
        return None                      # 不买：不发标签（A=NOOP）

    J_ecn = (mu - v) * pi * c * DELTA - K_ECN
    if J_ecn > 0:
        return make_label(ECN, z)
    return None                          # 不发标签（A=NOOP），不是零披露

make_label(a, z):
    # 元数据只能依赖 (A, Z) 与公开状态；禁止依赖 X \ A
    tau = clamp(ALPHA * EMA_dt_report, TAU_MIN, TAU_MAX)   # 只由上报统计决定
    return Label(function = a.func,
                 priority = a.param,          # 仅 PRIORITY 用
                 egress_port = a.port,        # 仅 REDIRECT 用
                 action_id = a.audit_tier,
                 context_id = z.ctx_id,       # ★ 原样回填
                 epoch = server_epoch,
                 sequence = next_seq(),
                 expiry = round(tau / 65.536us))
```

## A.5 数值示例

标定常量（示例值，未上机调参；`v`/`μ` 已归一化，下表的"单位"是示例尺度）：

```text
R0 = 50 Mbps    T_v = 50 ms     H_max = 7      β = 0.15
μ0 = 0.002      κ_π = 3         κ_t = 0.5      κ_ecn = 0.001
α = 1.5         δ = 1.0         κ_σ = 1.0      T_age = 2 s
λ_A = 0.2       λ_B = 0         R_MIN = 1 Mbps  EPS = 1e-3
```

### A.5.1 三条流，同一个 context

context：`q = 9 → q̃ = 0.6`，`l = 6 → l̃ = 0.4`，`a = 15 → ã = 1.0`，
`Δq̃⁺ = 0.1`，`c = 1`。

```text
π  = (0.6 + 0.4 + 0.0)/3 + 0.5×0.1 = 0.3833
μ  = 0.002 × exp(3×0.3833) = 0.00632
```

| 流 | 私有状态 | `v` | 判决 | 输出 |
|---|---|---|---|---|
| A 视频会议 | `w=0.9, λ=0.2, D=15ms, r=120KB, ρ=0.01, R̂=10` | **0.2136** | `v > μ`，`h = round(7×0.530) = 4` | `PRIORITY_SET(4)` |
| B 批量备份 | `w=0.2, λ=0, D=∞, R̂=100, ρ=0.02` | **0.00133** | `v < μ`，`J_ECN = 0.00091 > 0` | `ECN_MARK` |
| C 视频会议（网络空闲） | 同 A，但 `q=l=0, Δ=0` | **0.2136** | `π = 0 → h = 0` | **不发标签（A=NOOP）** |

计算细节（流 A）：

```text
r_eff = 120×1024×8 / 1e6 / (1−0.01) = 0.993 Mbit
slack = 0.015 − 0.993/10 = −0.0843 s   →  u = 1（λ=0.2 不影响饱和值）
v     = 0.9/60 + 1×0.993/(0.05×100) = 0.015 + 0.1986 = 0.2136
h     = round(7 × clip((0.2136−0.00632)×0.3833/0.15, 0, 1)) = round(3.71) = 4
```

流 C 是重点：**私有侧一样急，但网络不稀缺，就不产生标签。**
"同时考虑两部分"在这里表现为一个乘积。注意 `NOOP` 仍是一个动作类；
只有"该 context 下所有流都落在 NOOP"时，`H(A|Z)` 才真正为 0。

### A.5.2 同一流，拥塞加深

流 A 保持不变，只让 `π` 从 0 升到 0.8：

| `π` | `μ` | 连续 `h*` | 取整 `h` | 解释 |
|---|---|---|---|---|
| 0.00 | 0.0020 | 0.00 | 0（NOOP） | 网络空闲，不需要买 |
| 0.15 | 0.0031 | 1.47 | 1 | 轻度拥塞 |
| 0.30 | 0.0049 | 2.92 | 3 | 轻度偏中 |
| 0.45 | 0.0077 | 4.32 | 4 | 中度拥塞 |
| 0.60 | 0.0121 | 5.64 | 6 | 重度拥塞 |
| 0.80 | 0.0220 | 1.02 → clip 1（h*=7） | 7（上限） | 接近打满 |

连续 `h*` 单调上升，没有"if-else 跳变"；离散 `h` 是它的量化台阶，台阶来自
动作字母表（`round` + `H_max`），不是判决阈值。对比一组
`if (q > 8) h = 4; else if ...`：后者的边界是手调常数，前者随 `π`、`v`、`μ`
连续移动。

### A.5.3 参数怎么设：标定常数 vs 判决阈值

| 常数 | 示例值 | 作用 | 怎么定 / 敏感性 |
|---|---|---|---|
| `R0` | 50 Mbps | 吞吐价值的半饱和点 | 取典型流速率分布的中位数；越大，吞吐项越平 |
| `T_v` | 50 ms | 时间价值尺度 | 取 deadline 分布的 10–90 分位；越小，紧迫度上升越快 |
| `H_max` | 7 | 优先级档位上限（`|A|=8`） | 由动作接口与实验精度定；`|A|` 是披露旋钮 |
| `β` | 0.15 | 档位增益标定 | 离线扫描使 `h` 覆盖 0..7；越小档位越高，不是判决阈值 |
| `μ0` | 0.002 | 价格基数 | 与 `v` 同量级：空闲时 `μ ≪ v`，拥塞时 `μ ~ v`；用历史 context 定 |
| `κ_π` | 3 | 价格弹性 | 用目标 `μ` 反推；越大，决策曲线越陡 |
| `κ_t` | 0.5 | 趋势权重 | 用 `Δq̃⁺` 分布定；越大越惩罚"正在恶化" |
| `δ` | 1.0 | ECN 让路收益系数 | 由 ECN 实验/仿真定 |
| `κ_ecn` | 0.001 | ECN 操作成本 | 由标记/重传/控制开销折算；是成本，不是状态阈值 |
| `T_age` | 2 s | 新鲜度时间常数 | 取上报间隔 EMA 的数倍；越旧动作越小 |
| `κ_σ` | 1.0 | RTT 膨胀归一化 | 由 `RTT_smooth/RTT_min` 分布定；`σ=1+κ_σ` 视为满稀缺 |
| `λ` | 0–0.9 | baseline latency sensitivity | 按 SLA/业务类型给初值；`λ<1` 保证 ECN 可达 |
| `R_MIN` | 1 Mbps | 数值守卫 | 取链路最低可分辨速率；不是策略阈值 |
| `EPS` | `1e-3` | 病态 `ρ` 守卫 | 传输层统计的数值容差 |
| `α, τ_min, τ_max` | — | expiry 标定与安全边界 | 由上报间隔分位与 tick 安全边界定 |

**这些是标定常数 / 安全边界，不是"队列超过 X 就升优先级"的判决阈值。**
唯一的"边界"是 `v = μ` 这个经济无差异点，它随 `z` 连续移动；`π` 的三路权重
若需要标定，可换成 `α_q+α_l+α_a=1`，本版用等权。

## A.7 阈值清单

| 数值边界 | 性质 | 能否去掉 |
|---|---|---|
| `queue/load/path` 的 16 个量化桶 | 上报压缩（线格式 4 bit） | 否；但可以改桶形状 |
| 上报冷却 100 ms | 防风暴 / 限速 | 否；是安全机制 |
| `τ_min / τ_max` | 有效期上下界 | 否；是安全边界 |
| `v > μ` | **经济无差异点**，随 `z` 连续移动 | 不是常数阈值 |
| `J_ECN > 0` | 成本收益比较 | 不是状态阈值 |
| `ã = 0` | 路径不可用的语义状态 | 不是可调参数 |
| `h* = 0` / `h = round(...)` | 动作字母表的量化 | 不是判决阈值；`|A|` 可调 |
| `R_MIN` | `R̂→0` 的数值守卫 | 不是策略阈值；防止 `1/R̂²` 爆炸 |
| `ρ ≥ 1−ε` | 病态重传比例的 fail-safe | 不是策略阈值；直接 NOOP |
| `c = exp(−age/T_age)` | 连续新鲜度折扣，无硬下限 | 不是阈值；旧 context 自然归零 |

可以写进论文的一句话：

> 本模型的决策**依赖**是连续的：动作档位由网络上下文决定的影子价格与端点
> 支付意愿之差连续生成，而不是一组手调的 `if (q > X)` 阶梯。剩下的数值边界
> 只有三类：上报量化桶（4 bit/指标）、动作字母表（优先级 0–7）、以及安全/数值
> 守卫（冷却、expiry、`R_MIN`、病态输入）；它们都是可标定的操作常数，不是
> 业务判决阈值。**注意这是"没有判决阈值"，不是"没有常数"** —— 常数的作用
> 由 A.5.3 的标定表逐项说明。

# Part B — 贡献 1 的形式化

## B.1 模型与威胁假设

### B.1.1 符号

| 符号 | 含义 |
|---|---|
| `X` | 流的私有状态（Part A 的 `x`），随机变量，取值 `x ∈ 𝒳` |
| `Z` | 网络上下文（Part A 的 `z`），取值 `z ∈ 𝒵` |
| `𝒜` | 动作字母表，`a ∈ 𝒜` |
| `F: 𝒳×𝒵→𝒜` | **参考决策函数**：掌握完整私有状态时的精确决策 |
| `φ: 𝒳×𝒵→ℳ` | 服务器编码器（生成标签），`ℳ` 为标签空间 |
| `G: ℳ×𝒵→𝒜` | 交换机执行器（校验并执行标签） |
| `η` | 运行元数据：`flow_id, context_id, epoch, expiry, sequence` |
| `L = (A, η)` | 线上标签；`A := F(X,Z)` 为动作部分 |
| `Λ_T` | 前 `T` 轮的累计泄露 |

`F` 可以是任意参考策略；Part A 的价格模型是它的一个实例。理论部分只要求
`F` **确定**（同一个 `(x,z)` 永远给同一个动作）。

本文的标签：

```text
A   = F(x, z)
L   = ( A, η(a, z) )
```

**关键点**：`η` **允许**依赖动作 `a`、上下文 `z` 和服务器公开状态
（epoch / sequence / 时钟），但**不允许携带 `a` 之外关于私有状态 `x` 的信息**。
形式化地要求 `X ⊥ η | (A, Z)`。Part A 里"有效期只能由上报统计决定"
（A.3.4）正是这条约束的实例：若 `expiry` 用 `D_rem` 计算，它就会偷偷带上 `x`。

### B.1.2 威胁模型

| 观察者 | 能看到什么 | 对应保证 |
|---|---|---|
| **交换机**（执行者） | 明文动作（或解密后的动作） | 最小披露（B.3–B.5） |
| 链路观察者 / 中间盒 | 密文、包长、时序、频率 | 加密层（B.6） |
| 被动流量分析（Mazu 类） | 包长/间隔/方向 | 不在本文保证内，作为对比基线 |

**交换机必须知道动作才能执行**。因此"对交换机隐藏动作"在密码学上不可能
（除非可信执行环境 / 不经意执行）。本文保证的是**对执行者的披露最小化**，
而不是零知识。

## B.2 决策充分性

### 定义 1（决策充分性）

对任意 `x, z`：

```text
G( L(x,z), z ) = F(x,z)
```

左边是交换机用标签算出的动作，右边是服务器掌握完整私有状态时算出的动作。
**两者必须逐动作相同。**

### 命题 1（本文方案按构造满足充分性）

设标签 `L = (a, η)`，`a` 为动作；执行器 `G` 在满足下列条件时输出 `a`：

```text
(A1) 标签在 expiry 内到达
(A2) 标签的 context_id 与交换机当前轮次相等（实现上由 `exec_decide` 的 `ver_xor == 0` 承担）
(A3) 标签通过身份 / 重放 / 完整性校验
(A4) 功能在交换机白名单内，且该 block 能执行
```

则 `G(L(x,z), z) = F(x,z)`。

**证明**：`L` 的第一个分量就是 `a = F(x,z)`；`G` 在 A1–A4 下只做校验，然后
执行 `a`，不重新计算动作。因此输出恒等于 `F(x,z)`。∎

**这不是平凡结论，而是接口设计的核心**：充分性不是靠交换机"猜对"，而是靠
服务器把决定**做完**。传统方案是"暴露状态 → 交换机重新决策"，本文是
"服务器决策 → 交换机执行"。

### 推论 1（失败模式是单边的）

当 A1–A4 任一不成立时，执行器输出 `NOOP`（纯转发），**不会输出错误动作**。
定义遗憾：

```text
Δ(x,z) = U(F(x,z)) − U(NOOP) ≥ 0
```

则系统相对参考策略的损失为 `P(条件失效) · E[Δ]`，且永远非负。
实验中用"决策一致率" `P(G(L,z) = F(x,z))` 度量充分性。

## B.3 单次决策的最小披露

### B.3.1 泄露怎么度量

在给定上下文 `Z` 时，交换机能看到的标签 `L = φ(X,Z)` 是一个随机变量。
用**条件互信息**度量它对私有状态的信息量：

```text
leak(φ) = I(X; L | Z)
```

两点说明：

- **必须条件化在 `Z` 上**。上下文本身是公开信息，把公开信息算进"泄露"会虚高；
  比较不同方案时 `Z` 必须取同一个。
- **互信息是语义度量，不是语法度量**。它不问标签有多少比特，只问看完标签后
  `X` 的后验改变了多少。这正是"最小**语义**披露"的含义：标签定长 24 B
  不代表披露 192 bit，实际披露由"消除了 `X` 多少不确定性"决定。

### 定理 1（精确泄露恒等式）

设 `F` 确定，`A := F(X,Z)`，标签 `L = (A, η)`。则

```text
I(X; L | Z) = H(A | Z) + I(X; η | A, Z)
```

**证明**：对互信息用链式法则（条件在 `Z` 上）：

```text
I(X; A,η | Z) = I(X; A | Z) + I(X; η | A, Z)
```

又因 `A = F(X,Z)` 是 `(X,Z)` 的确定函数，`H(A|X,Z) = 0`，所以

```text
I(X; A | Z) = H(A|Z) − H(A|X,Z) = H(A|Z)
```

代回即得。∎

这个等式比单独的下界更强：它把泄露**精确拆成两部分**——动作本身不可避免的
一部分，和元数据可能多带的一部分。

### 推论 2（下界与等号条件）

```text
I(X; L | Z) ≥ H(A | Z)
等号 ⟺ I(X; η | A, Z) = 0，即 X ⊥ η | (A, Z)
```

**元数据设计规则**：`η` 可以依赖 `A`、`Z` 和公开状态，不能依赖 `A` 之外的 `X`。
若违反，多泄露的量恰好是 `I(X; η | A, Z)`，可以单独算出来。

| 字段 | 允许的依赖 | 违反示例 |
|---|---|---|
| `flow_id` | 流本身的公开标识 | 用私有状态派生的假名 |
| `context_id` | `Z` 原样回填 | 由私有状态派生 |
| `expiry` | 上报间隔统计 `EMA(Δt_report)` | 直接用 `D_rem` 计算 |
| `priority` | 动作参数本身 | 附带"剩余量档位"诊断字段 |
| `sequence` | 服务器计数器 | 按私有状态排序 |

Part A 规定"有效期只由上报统计决定"（A.3.4），正是为了让第二项为 0。

### 定理 2（动作标签恰好达到下界）

取

```text
φ_c(x,z) = ( F(x,z), η(z) )
G_c((a,η), z) = a
```

则 `(φ_c, G_c)` 满足决策充分性，且

```text
I(X; L | Z) = H(A | Z)
```

**证明**：`η(z)` 只依赖 `z`，故在给定 `(A,Z)` 后 `η` 与 `X` 独立，
`I(X;η|A,Z) = 0`，由定理 1 得等号。∎

公开随机数（如加密 nonce）同理：它在 `Z` 下与 `X` 独立，不改变结论。

**结论**：对确定性 `F`，`H(A|Z)` 就是完成一次精确决策的**精确最小**语义披露，
动作标签恰好达到它。注意方向：**不是** `I(X;L|Z) ≤ H(A|Z)`——那是反的。

### 推论 3（必要区分与最小充分统计量）

- 若 `F(x,z) ≠ F(x',z)`，任何正确接口都必须让 `x` 与 `x'` 产生不同的标签
  （否则执行器无法同时输出两个动作）。
- 若 `F(x,z) = F(x',z)`，再区分二者对正确性没有贡献。

所以 `F(·,z)` 诱导的划分是**唯一的最粗充分划分**；动作就是它的类标号。
这与统计学中"函数 `g(X)` 的最小充分统计量就是 `g(X)` 本身"是同一件事。

### 推论 4（零披露的真正条件，与 NOOP 的区别）

若某个 context 下动作与私有状态无关，即 `H(A|Z=z) = 0`，则最小披露为 0，
该规则应下推到交换机本地策略 `b(z)`（前提是交换机有能力独立执行它）。

**注意**："不发标签"本身**不是**零披露。标签缺席是可观测事件，它编码了
`A = NOOP`，会计入 `H(A|Z)`。只有当动作在整个 context 下恒为 `NOOP`
（对任意 `x` 都一样）时，缺席才不携带关于 `X` 的信息——这正是 Part A 的流 C：
`π = 0` 时 `h* = 0` 且 `J_ECN < 0` 对**任何** `v` 都成立，动作与 `X` 无关。

反例：若某 context 下有些 `x` 会触发 PRIORITY、有些不会，那么"这一轮没发标签"
就告诉观察者"这条流的私有状态不紧急"，这部分信息照样计入 `H(A|Z)`。

### 推论 5（数值例：一次决策泄露多少）

设 `X` 均匀取 `{1,2,3,4}`（`H(X) = 2` bit），上下文固定。参考策略把四个状态
分成三类，类大小 `2/1/1`：

```text
F(1) = F(2) = a₁,   F(3) = a₂,   F(4) = a₃
P(A) = (1/2, 1/4, 1/4)
```

则

```text
H(A|Z) = H(1/2, 1/4, 1/4) = 1.5 bit
```

对比：

| 接口 | 披露量 | 说明 |
|---|---|---|
| 完整状态（回传 `x`） | 2 bit | 消除 `X` 的全部不确定性 |
| 动作标签 | **1.5 bit** | 恰好达到下界 |
| 标签 + 私有诊断字段 | > 1.5 bit | 多出的部分 = `I(X;η\|A,Z)` |

类内后验：看到 `A = a₁` 后，`X=1` 与 `X=2` 各为 `1/2`，与先验在类内的相对
比例一致——标签只揭示"落在哪一类"，不揭示类内位置（定理 3）。

**先验依赖**：`H(A|Z)` 的数值取决于 `X` 的分布 `P_X`。同样的划分、不同的
先验会得到不同的泄露量。本文所有数值例都给定先验（通常取均匀），论文中
必须写明。

### 备注（`F` 随机化时）

若 `F` 含服务器私有随机性（例如随机打破平局），`A` 不再由 `(X,Z)` 确定，
`H(A|X,Z) > 0`，此时最小披露是 `I(X;A|Z)` 而不是 `H(A|Z)`；发送动作仍是
最优接口，只是下界本身更小。`H(A|Z)` 是**确定性 `F`** 的特例。本文的价格模型
是确定性的（`round` 是确定运算），所以正文用 `H(A|Z)`。

## B.4 私有状态不可区分性

### 定理 3（同一动作类内完全不可区分）

设 `(φ_c, G_c)` 如定理 2。固定同一条流（`flow_id` 相同），若 `x₁, x₂` 满足
`F(x₁,z) = F(x₂,z) = a`，则

```text
P(L | X=x₁, Z=z) = P(L | X=x₂, Z=z)      （两者都是 (a, η(z)) 处的点质量）
```

即标签**与"类内哪个状态为真"统计独立**；观察者的后验为

```text
P(X=x | L=(a,η), Z=z) = P(X=x|z) · 1[F(x,z)=a] / P(F(X,z)=a|z)
```

**证明**：`η(z)` 与 `x` 无关，`a = F(x,z)` 在两个状态下相同，故两状态下标签
逐比特相同，分布相同。对后验用贝叶斯公式即得。∎

**推论**：若类内先验均匀，则后验在类内仍均匀。标签只揭示"落在哪个类"，
不再揭示类内位置。

**例子**：同一条流的两份候选私有状态（deadline 分别为 7.3 ms 与 7.5 ms，
例如来自两次测量），在当前 context 下都落入"第 4 档"动作类，则交换机收到的
标签完全相同，无法分辨 7.3 与 7.5。**这就是"所有需要进入高优先级队列的
deadline 都映射到同一动作语义"的形式化版本。**

**注意粒度是旋钮**：动作档位从 8 档降到 3 档，类会变粗，`H(A|Z)` 下降，
不可区分性更强，但控制精度也随之下降。这正是 Part B.5 的 Pareto 曲线。

## B.5 跨时间组合泄露

单次最小不等于多次最小：每个 context 诱导一个不同的划分，连续观察是划分的**求交**。

### B.5.1 精确表达式

设观察到 `T` 轮 `(L_1..L_T)`，context 序列 `(Z_1..Z_T)`，动作标签如定理 2：

```text
Λ_T = I(X; L_{1:T} | Z_{1:T})
    = H(A_{1:T} | Z_{1:T})                      （同定理 2 的论证）
```

因为 `A_t = F(X,Z_t)` 由 `X` 与已知的 `Z_t` 确定，所以 `Λ_T` 就是**动作轨迹的熵**。

### B.5.2 用"见过的不同 context 数"界定

令 `𝒵_obs = {z_1, ..., z_T}` 为出现过的**不同** context 集合，`K = |𝒵_obs|`。
同一 context 重复出现不会产生新信息（动作必然相同），于是

```text
Λ_T = H( (F(X,z))_{z ∈ 𝒵_obs} | 𝒵_obs )
    ≤ K · log|𝒜|
    ≤ min( H(X), K·log|𝒜| )
```

- `H(X)` 上界对连续状态也成立：真正决定泄露的是**诱导出的有限划分**，不是状态的熵。
- **重复动作不加泄露**：若多个 context 下动作相同，`(F(X,z))_z` 的分布更集中，
  `H` 更小。服务端对同一动作重新签发新 `context_id`，披露几乎不增加。

### B.5.3 泄露速率

设上下文变化率为 `λ_c`（次/秒），观察窗口 `T`：

```text
K ≤ 1 + λ_c · T
Λ_T ≤ (1 + λ_c T) · log|𝒜|
```

四个旋钮全部出现在这里：

| 论文里的说法 | 公式里的量 | 协议里的旋钮 |
|---|---|---|
| context 粒度 | `\|𝒵\|`、划分粗细 | 每指标 4 bit 的桶边界 |
| 动作数量 | `\|𝒜\|` | 优先级 0–7；动作族个数 |
| 标签更新频率 | `λ_c` | 上报冷却 100 ms、变化才报 |
| 观察时间 | `T` | 标签有效期、观察窗口 |

**注意**：本协议要求"每个新 context 轮次必须重新签发标签才能维持动作"，
所以 `λ_label ≈ λ_c`。缓存只能省掉**同一轮内的重复签发**，不能省掉跨轮次的。
这是上下文绑定机制的直接代价，也是 `λ_c` 成为主要泄露旋钮的原因。

### B.5.4 数值例：两次划分的联合泄露（可手算）

设 `X` 均匀取 `{1,2,3,4}`，`H(X) = 2` bit。两个 context 各诱导一个二分：

```text
z₁:  A₁ = 1[ X ∈ {3,4} ]        （切一刀：{3,4} | {1,2}）
z₂:  A₂ = 1[ X ∈ {2,3,4} ]      （切另一刀：{2,3,4} | {1}）
```

四个格子概率均为 `1/4`，联合分布为：

| | `A₂=0`（X=1） | `A₂=1`（X∈{2,3,4}） |
|---|---|---|
| `A₁=0`（X∈{1,2}） | 1/4 | 1/4 |
| `A₁=1`（X∈{3,4}） | 0 | 1/2 |

所以

```text
Λ₂ = H(A₁,A₂) = H(1/4, 1/4, 1/2) = 1.5 bit
上界 min(H(X), K·log|𝒜|) = min(2, 2·1) = 2 bit
```

上界不紧的原因一目了然：`A₁=1, A₂=0` 是空事件，两刀并没有把 `X` 切成
4 个等可能格子。若再来第三个 context 把 `{3,4}` 切开
（`A₃ = 1[X=4]`），三个动作就能唯一定位 `X`，`Λ₃ = 2 = H(X)`，封顶。

**连续状态的直觉**：若 `X` 是一维 deadline、`𝒜` 有 8 档，单个 context 把
`X` 切成 8 段；第二个 context 的桶边界平移半格，两次求交最多 16 段
（4 bit）。每多一个"边界位置不同"的 context，最多再加 `log|𝒜|` 比特，
`K` 个 context 可把 `X` 定位到 `|𝒜|^{-K}` 量级——这就是为什么"持续上报
精确状态"比"变化才报"危险得多。

### B.5.5 Pareto frontier

定义

```text
PF = { ( U(θ), Λ_T(θ) ) : θ = (桶宽, |𝒜|, λ_c) }
```

`U(θ)` 可以是相对参考策略 `F` 的平均效用，或决策一致率。三个旋钮同时抬升
效用与泄露，因此构成一条前沿：

| 旋钮 | 调粗 → | 调细 → |
|---|---|---|
| 桶宽 | 泄露↓、控制精度↓ | 泄露↑、精度↑ |
| `\|𝒜\|` | 泄露↓、动作粒度↓ | 泄露↑、粒度↑ |
| `λ_c`（上报更频繁） | — | 泄露↑、陈旧损失↓ |

论文实验 2（私有状态重构风险）画的就是这条前沿：横轴泄露（或攻击者重构误差），
纵轴调度性能。

## B.6 加密层

### B.6.1 能保护什么，不能保护什么

- **不能**对执行者隐藏动作：`G` 必须输出 `a`，否则定义 1 不成立。
  这是接口语义决定的，任何加密都绕不过。
- **能**对链路观察者、中间盒、旁路采集隐藏动作，使它们只能看到时序/长度元数据。
- **能**提供真实性、防重放、防误投（与 `switch_id`、`epoch`、`sequence` 配合）。

### B.6.2 AEAD 封装

把标签拆成公开头与决策载荷：

```text
公开头 H_pub = ⟨version, msg_type, switch_id, epoch, flow_id,
                context_id, expiry, sequence⟩
决策载荷 D   = ⟨function_id, action_id, priority, egress_port⟩

(ct, tag) = AEAD.Enc(K_s, nonce = sequence, aad = H_pub, pt = D)
线格式    = H_pub || ct || tag
```

- `aad = H_pub` 把动作绑定到流、轮次、纪元、有效期，**不能把标签搬到另一个
  上下文里复用**。
- `nonce = sequence` 保证同一 key 下不重复；`epoch` 切换时轮换 key。
- 观察者无 `K_s` 时只看到密文；在 AEAD 的 IND-CPA 保证下，无法区分两个动作。

### B.6.3 两种部署形态

| | 形态 A（当前实现） | 形态 B（加密） |
|---|---|---|
| 谁解析标签 | P4 parser 直接解析 `0x4444` | 交换机控制面 agent 解密 |
| 谁写寄存器 | P4 数据面 | agent 经 bfrt 写 `reg_label*` |
| 链路保密 | ❌ 明文动作 | ✅ 仅密文 |
| 数据面开销 | 解析 + 校验占 stage | 不解析标签，**可能省 stage** |
| 控制面时延 | 无 | 多一跳 agent 处理 |

形态 B 需要新标签封装（AEAD 有 16 B 以上的扩展），属于**线格式改动**，
必须按 `md/01 → constants.py → headers.p4 → 编译` 的顺序走，本文不实施。

### B.6.4 轻量替代：带密钥的动作码本

若不想扩长标签，可以让服务器把动作编码成一个**带密钥的伪随机码字**：

```text
token = PRF(K_s, flow_id || context_id || sequence) 的低 8 位
交换机侧由 agent 装载 "token → 动作" 的码本表
```

线上只看到看似随机的 `token`，语义保密；代价是码本由控制面维护。
这同样属于形态 B（agent 参与），不是纯数据面方案。

### B.6.5 侧信道

| 侧信道 | 泄露什么 | 缓解 |
|---|---|---|
| 标签包频率 | context 变化率 ≈ `λ_c` | 100 ms 冷却已限制到 ≤10/s |
| 标签包长度 | 动作族数量（明文版） | 固定 24 B；加密版固定总长 |
| 标签包时序 | 决策时刻 | 批量/抖动发送 |
| `flow_id` | 哪条流被调度（可跨轮关联） | 每 epoch 用 `PRF(K, 5-tuple)` 假名 |
| 上报方向 `0x5555` | 量化等级本身 | 同一密钥加密上报，或只在受信域内 |

**上报方向也要保护**：报告虽然只含量化等级（已经最小化），但在不可信链路上
仍然暴露"网络在何时紧张"。Week1 用 CRC16 占位，真实加密按计划放到后续。

## B.7 接口伪代码与离线审计

### B.7.1 编码器 encode（服务器）

```text
encode(x, z):
    a   = F(x, z)              # ★ 唯一读取 x 的地方
    eta = eta_of(a, z)         # 只依赖 (A, Z) 与公开状态
    return (a, eta)
```

实现约束：

- `a = F(x,z)` 之后，函数体**不得再读 `x`**；
- `eta_of` 的签名里就没有 `x`，从类型上排除误用；
- `expiry` 用 `EMA(Δt_report)`，`context_id` 原样回填（见 A.4 的 `make_label`）。

`F` 在本文就是 A.4 的 `decide`，因此 `encode` 的其余部分与 A.4 完全一致。

### B.7.2 执行器 execute（交换机）

```text
execute(L, z, caps, state):
    (a, eta) = L
    if expired(eta, state.clock):                  return NOOP   # A1
    if eta.context_id != z.ctx_id:                 return NOOP   # A2
    if not (auth_ok(eta) and seq_ok(eta.sequence)): return NOOP   # A3
    if a.function not in caps:                     return NOOP   # A4
    return a                                                     # 不重算动作
```

执行器**只校验、不决策**。这是充分性（定义 1）在代码层面的体现：
`execute` 的返回值恒等于标签里的 `a`，而 `a` 是服务器算好的。

### B.7.3 审计器 audit（离线）

```text
audit(encode, D):                      # D = {(x_i, z_i)} 采样
    for (x, z) in D:
        L = encode(x, z)
        assert execute(L, z) == F(x, z)            # 定义 1：充分性
    assert meta_depends_only_on(encode, {"A", "Z"})  # 元数据规则（静态检查）
    return I_hat(X; L | Z), H_hat(A | Z)
```

估计注意事项：

- 离散 `A`：插件估计 `Ĥ(A|Z) = Ĥ(A,Z) − Ĥ(Z)`；小样本有负偏差，可用
  held-out 数据或 Miller–Madow 修正；
- 连续 `X`：`I(X;L|Z)` 用分箱或 k-NN 估计，结果依赖分箱，报告时必须写明；
- 真正要检验的是**差** `I(X;L|Z) − H(A|Z) ≈ 0`，它对估计器偏差比绝对值更稳健。

### B.7.4 假设与边界

| 编号 | 假设 | 若不成立 |
|---|---|---|
| H1 | `F` 确定 | 下界换成 `I(X;A\|Z)`（见 B.3 备注） |
| H2 | `Z` 在决策时刻两侧一致、可观测 | `context_id` 校验失败 → `NOOP` |
| H3 | `X ⊥ η \| (A,Z)` | 泄露多出 `I(X;η\|A,Z)` |
| H4 | 无执行器侧信道（功耗、缓存、精确时序） | 不在互信息模型内，需单独分析 |
| H5 | 先验 `P_X` 已知或已给定 | 等式仍成立，但 `H(A\|Z)` 的数值随先验变化 |

在 H1–H5 下等式是**精确**的，不是近似。条件失效只带来遗憾
（`Δ = U(F) − U(NOOP) ≥ 0`），不会产生错误动作（推论 1）。

## B.8 可直接写进论文的命题

**P1（决策充分性）** 标签接口下，交换机在有效期与上下文绑定成立时执行的决策，
与掌握完整私有状态时的决策逐动作相同：`G(L(x,z),z) = F(x,z)`。
条件失效时退化为安全基线 `NOOP`，误差单边。

**P2（单次最小披露）** 对确定性参考策略 `F`，任何正确接口 `L=(A,η)` 满足

```text
I(X;L|Z) = H(A|Z) + I(X;η|A,Z) ≥ H(A|Z)
```

当 `η` 不携带 `A` 之外的私有信息时（本文的元数据设计规则），动作标签恰好
达到等号。因此 `H(A|Z)` 是完成一次精确决策所需的**精确最小**语义披露。
若 `F` 随机化，最小值改为 `I(X;A|Z)`。

**P3（类内不可区分）** 若 `F(x₁,z)=F(x₂,z)`，两个私有状态产生的标签相同，
后验等于类内先验；标签只揭示动作类，不揭示类内位置。

**P4（跨时间泄露）** 累计泄露为动作轨迹的熵：

```text
Λ_T = H(A_{1:T}|Z_{1:T}) ≤ min(H(X), K·log|𝒜|) ≤ (1+λ_c T)·log|𝒜|
```

其中 `K` 是观察窗口内出现过的**不同 context 数**（重复同一 context 不新增
信息），`λ_c` 是 context 变化率。上界不一定紧（B.5.4 的例子只到 1.5 bit，
上界是 2 bit），它给出的是量级与旋钮。context 粒度、动作数量、更新频率、
观察时间共同决定泄露，形成效用—泄露的 Pareto frontier。

**文字版（可改写进引言/贡献段）**：

> 我们把加密传输的可观测性从"字段可见性"重新定义为"决策可执行性"：
> 网络接口的最小单位不是状态字段，而是"在当前上下文下可执行的动作"。
> 服务器的私有状态只通过它诱导的动作进入网络。在此接口下，
> (i) 交换机执行的决策与掌握完整私有状态时一致；
> (ii) 任何正确接口都必须至少传达动作所对应的信息，而动作接口恰好达到该下界；
> (iii) 同一动作类内的私有状态在交换机看来完全不可区分；
> (iv) 多次观察的累计泄露由上下文变化次数与动作字母表大小共同界定。
> 加密层进一步把动作对非执行者隐藏，使链路观察者只能看到时序元数据。

# 汇报提纲

1. **问题**：网络要决策，但不该拿到完整私有状态。
2. **接口**：`g(L(x,z), z) = F(x,z)`；动作标签代替状态字段。
3. **模型（Part A）**：输入 `(x, z)` → 支付意愿 `v` 与影子价格 `μ` → `v>μ` 买优先级、
   `v<μ` 让带宽、都不成立就不发标签。给公式与一条数值曲线。
4. **最小性（Part B）**：`I(X;L|Z) = H(A|Z)`，任何正确方案都 ≥ 它；
   类内不可区分；多次观察按 `K·log|𝒜|` 累积。
5. **加密**：隐藏的是"谁能看"，不是"交换机需要多少"；AEAD + 码本两种形态。
6. **验证计划**：决策一致率、重构风险 Pareto、更新时延、缓存命中率、拒绝率、资源开销。
